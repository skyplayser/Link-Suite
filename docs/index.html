What Link-Suite does

A new interface, a start animation of its own, polish for the Mac and a Windows installer without admin rights – on top of installing and updating from GitHub.

Every program at a glance

The numbers that matter at the top – updates, running, installed, in development – and the programs in groups: Installed, Development, Available, Coming soon. One pill per card.

Install and update from GitHub

LJ Link and VJ-Link straight from their GitHub releases, with one click, every file checked with SHA-256. Updating works again and again; a stalled download stops cleanly.

LJL Link for the club stick

“To the stick” puts LJL Link into a folder or straight onto the club's USB stick, with a short guide. The club's club.json still goes next to it by hand.

Start animation

The program icons fly into their cards. At most about 2 seconds, skippable, calm with “reduce motion”, and it can be switched off.

At home on the Mac

Window without title bar, menus with shortcuts, About window, progress and update count on the Dock icon, quiet notifications, menu bar icon, welcome card and a proper DMG window.

Windows without admin rights

The installer installs for your user only, in German or English.

Updates itself

Link-Suite checks its own releases the same way. The new version is put in place when you quit.

Developer view only when needed

Developer projects with log bar and Stop appear only once you set developer folders. Without them: no npm commands, no developer pills.

Suite chat with EMERGENCY

The same chat room as LJ Link, LJL Link and VJ-Link, without a server. Optionally Link-Suite stays in the menu bar (off by default).

Principles of the suite

Listens. Shows. Asks.

The same rules hold for every program of the Link-Suite, and for Link-Suite itself.

It listens

Link-Suite controls no device and no other program on the network. Other computers are only shown, never touched.

No telemetry

No usage data, no crash reports, no tracking. This website has no trackers either.

No server, no account

The suite chat runs between the programs in the local network, without a server and without sign-up.

Internet only to GitHub

Link-Suite only asks GitHub for new releases of the suite and downloads the ones you choose. Every file is checked with SHA-256 before it is installed.

Asks first, honest about the state

Nothing happens without a click. Alpha, beta, “in development” and “not signed” are shown where they apply.

What leaves your computer

Link-Suite sends into the local network while the suite chat is on (on by default, switch it off in the settings), and it asks GitHub for releases.

The chat is not encrypted: anyone in the same network can read along, and the programs in the room pass the latest messages on to newcomers. Do not write anything confidential. A developer project you start is its own program – what it does, including npm loading packages, is up to that project.

How a download is checked

  • SHA-256 against GitHub: Link-Suite checks every file with SHA-256 against the checksum GitHub gives for the release, and the size has to match. This protects against broken and swapped downloads – but not against a GitHub account that has been taken over.
  • No checksum, no install: if a release has no checksum for the file, Link-Suite installs nothing and only opens the release page.
  • A suite signature comes later: a signature of the suite's own (SHA256SUMS.sig) is planned. If a release already carries one, Link-Suite checks it today, and a wrong one stops the install.
  • Only from the program's own repository, only over HTTPS from GitHub. On a Mac the download has to contain the right program in the right version; a running program is never replaced or quit.

Neither Link-Suite nor the programs it installs are signed with Apple or Microsoft. The programs are written to disk by Link-Suite itself, the same way the built-in updaters of LJ Link and VJ-Link work, so macOS does not check them itself – Link-Suite's checks above are what stands in for it.

EMERGENCY is a heads-up pop-up for the team, not an alarm or safety system. It is an alpha, can fail or arrive late, and anyone in the same network can trigger it. It does not replace announcements, radios or the event's safety plan.

Honest about the state

What is tested, what is next

Tested for 0.3.1 – macOS ready for release

  • Install and update, for real: VJ-Link from GitHub installed, then updated twice in a row – clean each time, no leftovers. Cancelling leaves the installed app unchanged. (Developer build with the same code; the packaged app does not allow remote control.)
  • Slow downloads against a throttled local server, in Node and under Electron.
  • Interface in day and night, German and English, at four window sizes; the start animation measured frame by frame.
  • Build and 146 unit tests pass; both DMGs build; the packaged app started with real data.

Only in the code, or not yet

  • Only in the code: Dock progress and notifications, the DMG window in the Finder, the system light mode at start.
  • Not tested: a throttled real GitHub download, the self-update (no release of Link-Suite yet), Link-Suite between two real computers or in a club.
  • Windows: not tested yet.

Next

  • A suite signature of its own on every release (SHA256SUMS.sig).
  • VD-Link through Link-Suite once its releases are public; NET Link, Crew Link, PL Link and dB Link when they are ready – no dates.
  • Prepare club stick with club.json; Bonjour for the web interfaces of suite programs.

Limits

  • Not signed with Apple or Microsoft: macOS (Gatekeeper) and Windows (SmartScreen) warn on the first start. After an update macOS may ask about the local network again.
  • Windows: firewall rules that Windows creates on the first start stay after uninstalling (removing them would need admin rights).
  • Private repositories (VD-Link today) cannot be installed through Link-Suite; it never asks for tokens.

First start: getting past the warning

Link-Suite is not signed with Apple or Microsoft. Signing costs money and says nothing about safety, but both systems warn once on the first start because of it. Only download Link-Suite from this page or from GitHub.

macOS

Message: “Link-Suite” Not Opened – Apple could not verify “Link-Suite” is free of malware.

  1. Open the .dmg and drag Link-Suite into Applications.
  2. Start Link-Suite once and click Done at the warning (not “Move to Trash”).
  3. Open System Settings → Privacy & Security, scroll down and click Open Anyway next to Link-Suite. Confirm with your password or Touch ID, then Open.
  4. Allow Local Network when asked. Link-Suite needs it for the suite chat and ON THE NETWORK.

After an update macOS may ask about the local network again, because the app is not signed and macOS sees the new version as a new app. Allow it again.

Windows

Message: “Windows protected your PC” (Microsoft Defender SmartScreen).

  1. Run Link-Suite-windows.exe.
  2. In the blue window click More info, then Run anyway.
  3. Click through the installer. It installs for your user only and needs no admin rights.
  4. If the Windows Firewall asks, tick Private networks and allow access (for the suite chat).

Quick start

  1. PROGRAMS: Install, Update or Start on a card.
  2. LJL Link: “To the stick” – a folder or the club's USB stick.
  3. ON THE NETWORK: see which suite programs run where.
  4. SETTINGS: your name and place for the chat, language, day or night.
  5. The speech bubble at the top right opens the chat. EMERGENCY is the yellow button.

Some virus scanners flag unknown, unsigned programs as a precaution. Questions or problems? Discord or fehlermelden@nextphilm.de. Link-Suite has no built-in “Report a problem” yet.
